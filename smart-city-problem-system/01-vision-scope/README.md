# Предложения по улучшению проекта

## 1. Дополнительные функции системы

### 1.1. Проверка похожих заявок
Перед созданием новой заявки система проверяет наличие похожих обращений по указанному адресу и категории проблемы.

Если похожая заявка уже существует, пользователь может перейти к ней вместо создания дубликата.

**Преимущества:**
- Снижение количества повторных обращений.
- Упрощение работы операторов.
- Более эффективная обработка городских проблем.

**Приоритет:** высокий.

### 1.2. История изменения статусов
Для каждой заявки сохраняется история изменения статусов:
- Создано.
- Принято.
- Назначен исполнитель.
- В работе.
- Выполнено.
- Закрыто.

Пользователь может отслеживать ход выполнения заявки, а оператор — контролировать процесс её обработки.

**Преимущества:**
- Прозрачность работы системы.
- Возможность отслеживать все этапы обработки обращения.
- Упрощение контроля со стороны городских служб.

**Приоритет:** высокий.

### 1.3. Подтверждение выполнения работ
После устранения проблемы исполнитель прикрепляет фотографию результата и краткий отчёт о выполненных работах.

Житель может подтвердить результат или сообщить, что проблема не устранена полностью.

**Преимущества:**
- Повышение прозрачности работы городских служб.
- Подтверждение фактического выполнения работ.
- Возможность повторного рассмотрения нерешённых проблем.

**Приоритет:** высокий.

### 1.4. Интерактивная карта городских проблем
На карте отображаются зарегистрированные обращения с возможностью фильтрации по:
- Категории проблемы.
- Статусу обращения.
- Району города.

При выборе отметки пользователь может ознакомиться с описанием проблемы и текущим статусом её решения.

**Преимущества:**
- Наглядное отображение городских проблем.
- Возможность обнаруживать проблемные районы.
- Снижение количества повторных обращений.

**Приоритет:** высокий.

### 1.5. Контроль сроков выполнения заявок
Для каждой категории проблем устанавливается нормативный срок решения.

Если срок приближается к окончанию или уже истёк, система уведомляет оператора. Администрация получает возможность отслеживать просроченные обращения.

**Преимущества:**
- Своевременное выявление задержек.
- Повышение ответственности исполнителей.
- Улучшение контроля качества работы городских служб.

**Приоритет:** высокий.

## 2. Улучшение подачи заявок без регистрации

### 2.1. Защита от спама
Предусмотреть ограничение частоты отправки обращений и проверку подозрительной активности. При необходимости использовать CAPTCHA.

### 2.2. Безопасный доступ к заявке
Для проверки статуса заявки без регистрации использовать уникальный номер обращения и отдельный секретный код доступа.

Один только номер заявки не должен предоставлять доступ к её конфиденциальным данным.

### 2.3. Уведомления для незарегистрированных пользователей
Предусмотреть возможность указать номер телефона или адрес электронной почты для получения уведомлений об изменении статуса заявки.

### 2.4. Привязка заявки к аккаунту
Если пользователь зарегистрируется после отправки обращения, предусмотреть возможность привязать ранее созданную заявку к его аккаунту после подтверждения права доступа.

## 3. Дополнительные возможности

### 3.1. Приоритетность проблем
Предусмотреть возможность присвоения заявкам приоритета в зависимости от серьёзности проблемы.

Например, открытый люк или повреждение опасного участка дороги должны обрабатываться быстрее, чем незначительные неудобства.

### 3.2. Комментарии оператора
Добавить возможность запрашивать у жителя дополнительные сведения, необходимые для обработки обращения.

### 3.3. Повторное открытие заявки
Если проблема устранена не полностью, предусмотреть возможность вернуть заявку в работу после проверки результата.

### 3.4. Поиск и фильтрация обращений
Для сотрудников системы реализовать поиск по номеру заявки, категории, адресу, статусу и ответственному исполнителю.

### 3.5. Оценка качества решения
После выполнения заявки предоставить жителю возможность оценить результат работы и оставить отзыв.

### 3.6. Журнал действий
Сохранять информацию о действиях сотрудников: изменение статусов, назначение исполнителей и редактирование данных.

### 3.7. Доступность интерфейса
Предусмотреть удобный интерфейс для людей с ограниченными возможностями, включая читаемый текст, понятную навигацию и достаточный контраст элементов.

## 4. Этапы реализации

### Этап 1. Основной функционал
- Создание заявок зарегистрированными и незарегистрированными пользователями.
- Автоматическое присвоение номера заявки.
- Проверка статуса обращения.
- Разграничение прав доступа по ролям.
- Сохранение данных заявок.

### Этап 2. Улучшение обработки обращений
- История изменения статусов.
- Назначение исполнителей.
- Контроль сроков выполнения.
- Подтверждение выполнения работ фотографиями.
- Проверка похожих заявок.
- Защита от спама.

### Этап 3. Расширение возможностей
- Интерактивная карта городских проблем.
- Расширенная аналитика по районам.
- Автоматическое определение приоритетов.
- Формирование дополнительных отчётов.
- Улучшение доступности интерфейса.

## 5. Рекомендуемые приоритеты

В первую очередь рекомендуется реализовать проверку дубликатов, историю статусов и подтверждение выполнения работ фотографиями.

Эти функции дополняют существующие возможности системы и повышают удобство использования как для жителей, так и для городских служб.

При разработке важно обеспечить полный цикл обработки обращения:

1. Житель создаёт заявку.
2. Система регистрирует обращение.
3. Оператор проверяет заявку и назначает исполнителя.
4. Исполнитель выполняет работу и прикрепляет фотоотчёт.
5. Житель получает информацию о результате.
6. Система сохраняет историю обработки обращения.

**Главная цель улучшений** — сделать обработку городских проблем более прозрачной, удобной и контролируемой.
