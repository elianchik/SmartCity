## 4. Термины, бизнес-правила и сущности предметной области

В рамках анализа предметной области системы **«Умное управление городскими проблемами»** были выделены ключевые термины, бизнес-правила и сущности, определяющие логику работы системы.

### 4.1. Глоссарий (основные термины)

| Термин | Определение |
| :--- | :--- |
| **Инцидент** (Городская проблема) | Зафиксированный факт нарушения городской инфраструктуры или благоустройства, требующий вмешательства соответствующих служб. |
| **Заявитель** | Пользователь системы (гражданин), сообщающий о возникновении инцидента. |
| **Диспетчер** | Сотрудник городской службы, осуществляющий первичную обработку, классификацию и распределение заявок. |
| **Исполнитель** | Организация или сотрудник, ответственный за устранение инцидента. |
| **SLA** (Service Level Agreement) | Регламентный срок, отведенный на устранение проблемы определенного типа и приоритета. |
| **Геолокация** | Координаты места возникновения инцидента, используемые для точного определения адреса. |
| **Статус заявки** | Текущее состояние жизненного цикла проблемы (**Новая**, **В работе**, **На проверке**, **Решена**, **Отклонена**). |

---

### 4.2. Бизнес-правила

В ходе анализа были сформулированы следующие бизнес-правила, определяющие ограничения и логику функционирования системы:

1. **Гео-ограничение**  
   Создание заявки возможно только при условии, что координаты инцидента находятся в пределах географических границ муниципалитета.

2. **Автоматическая категоризация и SLA**  
   Каждой категории проблемы автоматически присваивается приоритет и нормативный срок решения.  
   * *Пример:* для прорыва трубы — приоритет «Критический» и срок **4 часа**;
   * *Пример:* для ямы во дворе — приоритет «Средний» и срок **5 дней**.

3. **Фото-фиксация**  
   Перевод заявки в статус **«Решена»** невозможен без загрузки исполнителем фотоотчета о проделанной работе.

4. **Модерация дубликатов**  
   При поступлении заявки с совпадающими координатами и категорией активной заявки, новая заявка помечается как **«Дубликат»** и прикрепляется к основной.

5. **Эскалация**  
   Если исполнитель не взял заявку в работу в течение **24 часов**, система автоматически уведомляет руководителя соответствующей службы.

6. **Анонимность**  
   Пользователь может подать заявку анонимно, однако для получения обратной связи об устранении проблемы требуется авторизация.

### 4.3. Сущности предметной области

На основе анализа терминов и бизнес-правил были выделены следующие сущности, которые лягут в основу проектирования базы данных:

| Сущность | Ключевые атрибуты |
| :--- | :--- |
| **Пользователь** | ID, ФИО, Email, Телефон, Роль (Гражданин, Диспетчер, Исполнитель, Админ), Рейтинг активности. |
| **Заявка** (Инцидент) | ID, Дата создания, Описание, Фото «До», Координаты (Lat/Long), Текущий статус, ID заявителя, ID исполнителя, Дедлайн (SLA). |
| **Категория проблемы** | ID, Название (Дороги, ЖКХ, Свет, Мусор), Ответственная служба по умолчанию, Норматив времени (SLA). |
| **Служба** (Организация) | ID, Название, Контактные данные, Руководитель, Зона ответственности (районы). |
| **Действие** (Лог) | ID, ID заявки, Тип действия (Создание, Смена статуса, Комментарий), Дата/Время, Автор действия, Текст комментария. |
| **Геозона** | ID, Название района, Границы (полигон на карте). |
